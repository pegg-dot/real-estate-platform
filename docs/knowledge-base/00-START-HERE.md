# Real Estate Knowledge Base — Start Here

This folder is Nate's persistent real estate brain. It solves one specific problem:
podcasts, YouTube videos, and books contain a huge amount of overlapping knowledge,
but if you drop each one into a separate chat, the insight dies when that chat's
context window fills up. Nothing connects. You can't see across sources.

**This knowledge base fixes that.** Every source gets distilled into a structured
note that lives here permanently. Because it's a file folder (not a chat), any future
session can read across *all* of it at once — comparing what Pace Morby says about
seller finance against what a different guru says, spotting contradictions, and
building one coherent model of how real estate actually works.

This is the "knowledge graph" you wanted. It's deliberately built from plain markdown
files so it's portable, future-proof, and AI-readable forever — not locked inside any
one app or chat.

## How it's organized

```
Knowledge Base/
├── 00-START-HERE.md          ← you are here (the map)
├── STRATEGY-REFRAMES.md      ← ⚠️ READ THIS: the hard truths + the better path
├── PRODUCT-SPEC-v1-to-v10.md ← the phased product, v1 → v10
├── ENGINEERING-BUILD-PLAN.md ← how we'd build it (Claude Code, repo, stack)
├── PLATFORM-BLUEPRINT.md     ← the system architecture (5 layers)
├── VISION-and-ROADMAP.md     ← the original framing of the "AI tool" idea
├── RESEARCH-FINDINGS.md      ← all cited web research (6+ streams)
├── Sources/                  ← one note per podcast / video / book
│   └── pace-morby--four-ways-to-make-money.md
└── Concepts/                 ← cross-source knowledge that grows over time
    ├── playbook.md           ← core frameworks + Nate's thesis (college-town rentals)
    ├── lead-generation.md    ← where deals come from + the actual tools used
    ├── creative-finance.md   ← sub2, seller finance, the equity math
    └── glossary.md           ← every term decoded (DTS, gator, EMD, bunnies...)
```

**Reading order if you're new to the folder:** `STRATEGY-REFRAMES.md` (the honest
strategic take) → `PRODUCT-SPEC-v1-to-v10.md` (what we'd build) →
`RESEARCH-FINDINGS.md` (the evidence) → `Concepts/` (the domain knowledge).

**Sources** = raw intake, attributed to who said it.
**Concepts** = the distilled, deduplicated truth that survives across sources.

When two sources disagree, the Concept file notes both positions. That's the whole
point — you get a synthesized view, not 40 disconnected chat logs.

## How to add a new source (the workflow)

Next time you have a podcast, YouTube video, or book chapter:

1. Paste the transcript (or link) into a chat in this project and say
   **"add this to the knowledge base."**
2. Claude will: create a new file in `Sources/`, extract the frameworks/tactics/tools,
   then fold anything new into the `Concepts/` files and flag any contradictions
   with what's already here.
3. Over time, `Concepts/` becomes a genuinely valuable, personalized real estate
   operating manual — tuned to your goal of buying with family-trust capital.

You never lose context again. Each session starts by reading this folder.
